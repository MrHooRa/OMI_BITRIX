# حالة تسليم تطوير نظام توصية الموظفين

الحالة الحالية: الإصدار `task-scoped-3.10` — 7 أكتوبر 2026.

أضيف حساب تلقائي لمرشح التنبيه وسبب ترشيحه من الأدلة المكتملة والحمل الحالي، لبتركس وديوان. يُعاد الحساب عند تغيّر المدخلات، مع عزل المستخدمين وحجب الترشيحات القديمة أو غير الموثوقة. تفاصيل التنفيذ في [دليل التنبيهات](AUTOMATIC_NOTIFICATIONS_AR.md)، وأدلة الاختبارات والحدود في [طريقة التحقق](testing.md). تبقى إصلاحات 3.9 في [دليل الإصلاحات](WORKFLOW_FIXES_AR.md).

أزيلت المجالات اليدوية والارتباطات المتعلمة بالقائمة القديمة. تستخدم المنصة الآن نموذج جمل E5 محليًا، وتجميع HDBSCAN بلا عدد مجالات ثابت، واستخراج عبارات c-TF-IDF، ونموذج BGE محليًا للتحقق من أزواج المهام. يبقى الإنجاز وحده أساس الترشيح، ويظل قرب المهام المعلقة مستقلًا. لا تغيير في الهوية البصرية أو أدوار الإسناد أو حدود الوصول.

في الإصدار السابق 3.8 نجحت 212 حالة اختبار في المسار الدلالي الفعلي، مع حظر الشبكة في اختبارات النموذج. نجح تثبيت المكتبات محليًا في بيئة جديدة وفحص الأوزان وفحوص Python/JavaScript. هذه اختبارات هندسية محدودة، وليست دقة إنتاجية.

أضيف تحسين تنفيذ النموذج ومقارنة المقاطع الطويلة، ومسار إعداد أمثلة للمراجعة وتدريب رأس BGE محليًا وتقييم المرشح. لا توجد أحكام بشرية معتمدة حاليًا؛ لذلك لم تُدرّب أوزان المؤسسة أو تُفعّل نسخة مدرّبة. FP32 هو الوضع الحالي، وINT8 تجربة غير مفعلة افتراضيًا. راجع [دليل الكفاءة والتدريب](MODEL_EFFICIENCY_AND_TRAINING_AR.md).

راجع [الدليل الحالي والمعادلات ومصادر البيانات](AUTOMATIC_DOMAINS_AR.md) و[طريقة التحقق](testing.md). البيانات القليلة لا تنتج مجالًا مخترعًا، والأسماء المكتشفة ليست تصنيفًا إداريًا معتمدًا. لا توجد دقة إنتاجية مقاسة، ولا عقد ديوان حي مثبت. الأرشيفات وملفات PDF السابقة لم تُعد بناؤها بهذا التحديث.

## سجل تسليم الإصدار 3.1

الأرقام والقياسات التالية تخص 3 أكتوبر 2026 والإصدار 3.1، وتبقى سجلًا تاريخيًا.

## ما تغيّر وفق المتطلبات

| المتطلب | التنفيذ الحالي |
|---|---|
| توزيع الضغط دون حد سعة | لا حد لعدد المهام في أهلية الموظف؛ الحمل والأولوية يؤثران في الترتيب فقط |
| مهمة المنشئ مسندة لنفسه | تظهر بانتظار منفذ حتى يؤكد المشرف أنه سينفذها بنفسه |
| موظف منفذ وليس مشرفًا | لا تمنحه صفة المنفذ صلاحية إعادة الإسناد؛ تُفحص أدوار المصدر الحية قبل الكتابة |
| اتساق المشرفين | قرار التنفيذ الشخصي وعلامة الإسناد غير المؤكد مشتركان للبوابة والمهمة، ويبطل القرار عند تغيّر الأدوار |
| عدم تشابه التذاكر وحدها | يستبعد المحرك معرّفات التذاكر وقوالب الاختبار؛ يحفظ اختصارات تقنية محددة ويدعم قاموس مرادفات صغيرًا |
| دليل الموظف | المهمة المستهدفة مستبعدة من أمثلتها؛ الإنجاز المكتمل منفصل عن العمل المفتوح؛ لا يُقدّم الموظف الفارغ كخبير |
| التحديث التاريخي | كل ساعتين أثناء تشغيل الخادم، مع فحص تشغيلي كل دقيقة؛ فشل الجلب لا ينشر فهرسًا جزئيًا |
| ديوان | نفس مسار التوصية والإسناد بعد اعتماد حقول المشرف والمنفذ وهوية التوكن؛ قراءة كل الصفحات والتفاصيل وفق المرجع |
| تحسين الرحلة دون تغيير الهوية | مساحة واحدة بتبويبات، مصدر واحد، بحث وترتيب للقائمة، ملخص مهمة، زر اختيار بجانب المرشح وحوار دليل للقراءة فقط |
| التاريخ والشفافية | سجل قرارات، تشخيص جودة البيانات، بحث وصفحات للتاريخ، وربط اختياري لحقول المصدر |
| التقييم | أداة محلية تقارن الترتيب بأقل ضغط وبالخبرة فقط باستخدام أحكام ملاءمة موثقة؛ لا تختلق تسميات من الإسناد القديم |

الألوان والخطوط والأصول المحلية محفوظة. لم تُغيّر تعيينات بتركس الفعلية أو سياسة الأهلية أو التوكنات أثناء الاختبار. عُرض حوار تأكيد الإسناد ثم أُلغي.

## أدلة التحقق

نجحت **103 اختبارات** محلية، وفحوص تركيب Python وJavaScript. فُحصت رحلة بتركس بالقراءة فقط، والواجهة بالعربية والإنجليزية وأحجام 1440 و390 و320 بكسل حسب الصفحة، دون تجاوز عرض المستند في المشاهد المختبرة. اختبارات ديوان والإسناد الفعلي تستخدم استجابات محاكاة.

أعاد اختبار الرواتب الحي مهام الرواتب دون مهام الشبكات أو الفواتير المرتبطة برقم الاختبار نفسه. جُمعت مهمتا أكتوبر 13 و31 في العرض مع حفظ المعرّفين والمنفذين. هذه عينة وظيفية وليست قياس دقة عام.

قياس محلي لـ10 آلاف سجل و50 موظفًا: بناء الفهرس 0.616 ثانية، وسيط التوصية 71.94 ملّي ثانية. القياس يخص دالة الفهرسة والترتيب ببيانات مولدة في الذاكرة، ولا يثبت أداء التطبيق الكامل على خادم 6 GB.

## ما لا يجوز اعتباره مكتملًا أو مثبتًا

1. **توافق ديوان الحي:** لا توجد وصلة وعقد أدوار مجرّبان هنا؛ أُنجز المحول والواجهة والاختبارات، وتحتاج المطابقة اعتماد مسؤول الخدمة داخل الشبكة.
2. **جودة الموظف وSLA كنقاط أداء:** أُضيف ربط الحقول وحفظها؛ لا تدخل الدرجة حتى تُعرف معانيها واتجاهها وتواريخها وموثوقية نسبتها للمنفذ.
3. **تفوق الخوارزمية:** أداة التقييم جاهزة، لكن يلزم توفير أحكام ملاءمة مستقلة ولقطات زمنية معتمدة. لا نعامل عدم اختيار الموظف كفشل.
4. **قبول الإنتاج:** اختبار الحجم الحقيقي وتزامن الملفات الشخصية وحدود API وخادم 6 GB والمشاركة الشبكية والوصول المساعد لم يُحسم بقياس التطوير.
5. **الإعدادات التنظيمية:** الأهلية والغياب خاصان بالملف الشخصي؛ لا يوجد تكامل HR أو إدارة سياسة مركزية أو ربط تلقائي لهويات النظامين.
