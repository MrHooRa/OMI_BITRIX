# التنبيه التلقائي بالموظف المقترح — 3.10

## ما الذي يظهر للمشرف؟

عند اكتشاف مهمة تحتاج منفذًا، تظهر في قائمة قرارات الإسناد دون أن يطلب المشرف تحليلها يدويًا. يتضمن تنبيهها:

- اسم الموظف الأعلى ترتيبًا ضمن المؤهلين الذين لديهم أدلة إنجاز مرتبطة بالمهمة.
- عدد المهام المكتملة ذات الصلة وعدد المهام المفتوحة المسندة إليه حاليًا.
- رابط أقرب مثال مكتمل لقراءة تفاصيله، مع بيان محدودية الدليل عند وجود نمط واحد فقط.

شريط التنبيهات خارج صفحة المهام يعرض اسم المرشح وملخص السبب، ويفتح المهمة بمصدرها الصحيح. الاسم اقتراح للمراجعة؛ الإسناد يبقى بقرار بشري وتأكيد وفحص صلاحيات المصدر. لا يرسل هذا المسار رسائل بريد أو تعليقات أو تنبيهات خارج التطبيق.

## التسلسل من الجلب إلى التنبيه

1. **جلب تشغيلي:** خدمة بتركس أو ديوان تقرأ المهام المفتوحة كل 60 ثانية أثناء تشغيل الخادم. تاريخ التحليل الكامل مستقل ويتحدث كل ساعتين. في ديوان تُستخدم إعدادات الحقول والتوكن الشخصي؛ لم يُفترض عقد جديد للواجهة.
2. **تحديد الحاجة للإسناد:** المهمة التي يحتفظ بها مشرفها تحتاج منفذًا حتى يؤكد أنه سيعمل عليها بنفسه. التنبيه يخص منشئ المهمة أو المراقبين المسجلين عليها. صفة المنفذ وحدها لا تمنح الإشراف.
3. **التحقق من الجاهزية:** يلزم تاريخ مكتمل الجلب، ودليل موظفين متحقق، ولقطة مهام مفتوحة لا يتجاوز عمرها 120 ثانية. فشل المصدر أو دليل الموظفين، أو بيانات مصدر مرتبط غير متاحة، يحجب اسم المرشح السابق.
4. **إعداد مدخلات موحدة:** النص والمشروع والتصنيف والأولوية، دليل الموظفين وضوابط الأهلية والغياب، الأدلة المكتملة والمؤرخة، والحمل الحالي. يمكن استخدام أعمال مصدر آخر فقط عند وجود ربط صريح للحسابات؛ تطابق الأسماء لا يثبت الهوية.
5. **جدولة الحساب:** بصمة تجمع مدخلات المهمة والتاريخ والأهلية والحمل وإصدار المحرك. تتغير البصمة عند تغيّر المدخلات المؤثرة. الاستطلاع المتكرر بمدخلات ثابتة لا يعيد الاستدلال. قائمة العمل تحتفظ بآخر نسخة منتظرة لكل مهمة ولكل ملف مستخدم.
6. **الاستدلال الخلفي:** عامل واحد لكل مصدر يستدعي محرك `rank` نفسه المستخدم في التحليل اليدوي، خارج قفل خدمة اللقطات. نماذج E5 وBGE المحلية ومحرك الاسترجاع الحالي مستخدمة كما هي؛ لم يُضف نموذج سحابي أو تدريب جديد.
7. **التحقق قبل النشر:** تُفحص هوية اتصال المستخدم وأدواره والسياسة ونسخة المدخلات وقرار التنفيذ وحالة الإسناد غير المؤكد. نتيجة مهمة تغيرت أو اختفت أثناء الحساب تُستبعد.
8. **عرض النتيجة:** ترسل الواجهة ملخصًا محدودًا: الموظف، أعداد الأدلة والحمل ومثال واحد. الواجهة المفتوحة تنتظر النتيجة بفحص كل خمس ثوانٍ أثناء حالة الانتظار، ثم تعود لدورتها المعتادة. الحساب لا يتطلب بقاء صفحة المهام مفتوحة.

## أساس اختيار الموظف

التنبيه لا يستخدم خوارزمية موازية. يرث قواعد الترشيح ومعادلاته الحالية:

- استبعاد غير المؤهلين للمشروع/التصنيف والغائبين وغير النشطين.
- استخدام إنجاز مكتمل بتواريخ صحيحة يسبق وقت التحليل؛ المهمة المستهدفة مستبعدة من أدلتها.
- فصل قرب العمل المعلق عن الترشيح المبني على الإنجاز.
- مقاومة التذاكر والقوالب والتكرار النصي؛ النسخ لا تضاعف رصيد الخبرة المستقل.
- ترتيب يجمع صلة العمل والخبرة والحمل بأوزان السياسة الحالية. لا يوجد حد أقصى لعدد المهام يمنع ترشيح الموظف، والدرجة ليست احتمال نجاح.

راجع [الخوارزمية ومصادر البيانات والمعادلات](AUTOMATIC_DOMAINS_AR.md) و[الكفاءة والتقييم](MODEL_EFFICIENCY_AND_TRAINING_AR.md). تسجيل الموظف كمنفذ عند إغلاق المهمة قرينة تاريخية، وليس إثباتًا مستقلًا لجودة أدائه.

## حالات التنبيه

| الحالة في API | ما يراه المستخدم |
|---|---|
| `pending` | جارٍ تحليل المهمة؛ لا يظهر اسم قبل اكتمال الحساب |
| `ready` | الموظف المقترح والسبب والدليل |
| `no_evidence` | لا توجد أدلة مكتملة مرتبطة لموظف مؤهل؛ يمكن المراجعة والاختيار اليدوي |
| `unavailable` | البيانات غير جاهزة/قديمة أو يوجد إسناد لم تُحسم نتيجته؛ يلزم التحقق |
| `failed` | تعذر الحساب أو نشر نتيجته؛ يعاد المحاولة بعد خمس دقائق ضمن دورة التحديث |

التنبيه المقروء يبقى في قائمة الإسناد. إذا تغيّر الموظف الأعلى ترتيبًا، يعود التنبيه غير مقروء. تحديث العدد أو توقيت الجلب مع بقاء الموظف نفسه لا يولد تنبيهًا مكررًا. عند التنفيذ الشخصي المؤكد أو زوال الحاجة للإسناد يختفي من قائمة التنبيهات.

## التخزين ونطاق الوصول

النصوص ونتيجة الاقتراح المصغرة تبقى في الذاكرة ضمن ملف المستخدم والاتصال. سجل القرار يحفظ معرف الموظف المقترح وحالة القراءة ومعرف التنبيه فقط ضمن بياناته التشغيلية الحالية؛ لا ينسخ وصف المهمة أو اسم الموظف أو مخرجات النموذج الكاملة. إعادة تشغيل الخادم تعيد بناء الاقتراح بعد جلب المصادر، مع حفظ حالة القراءة عندما لم يتغير المرشح.

الملخص `GET /api/recommendations?summary=1&source=bitrix`، أو `source=diwan`، يعيد أعلى مهمة غير مقروءة بحسب الأولوية والموعد. لا يعرض مهمة لمستخدم منفذ ليس مشرفًا عليها. فتح التنبيه لا يتجاوز فحوص الصلاحيات الحية في الإسناد الفعلي.

## ملفات التنفيذ والتحقق

- `notification_suggestions.py`: الجدولة، البصمة، حالات النتيجة، والتحقق قبل النشر.
- `recommendation_service.py` و`diwan_recommendations.py`: استقبال التحديثات وربط التنبيه بقرارات المهمة.
- `recommendation_routes.py`: اللقطة والملخص المحدود.
- `static/recommendations.js` و`i18n.py`: العرض بالعربية والإنجليزية ورابط الدليل.
- `tests/test_notification_suggestions.py`: اختبارات معزولة لا تُعدّل المصادر الحية.

التوقيت في الاختبارات محكوم ولا يثبت زمن خدمة إنتاجي. ازدحام المعالج وبداية تحميل النموذج وقوائم المشرفين الكبيرة قد تؤخر الاقتراح. لم يتوفر عقد ديوان حي للتحقق منه، واختباراته تستخدم محاكاة. دقة الترشيح الإنتاجية ما زالت تحتاج أحكام ملاءمة بشرية تمثيلية؛ لا تُستنتج من نجاح اختبارات التنفيذ.
