# Recommendation workspace review — 3.1

## Identity and hierarchy

The existing Tasks & similarity colors, fonts, theme variables and local assets are retained. The page is organized around task decisions rather than decorative cards or a separate recommendation destination.

## User journey

1. Choose Bitrix or Diwan once in the workspace header.
2. When assignment alerts exist, an unqualified first visit opens assignment decisions. Search/sort the queue, then review a task's narrative, supervisor, executor and deadline.
3. Inspect ranked candidates, completed examples and separate open-work evidence. Evidence opens a read-only dialog and never creates task folders.
4. Choose an employee beside their evidence, review the confirmation and submit deliberately. Personal execution can only be confirmed by the current supervising executor.
5. Inspect the decision log and history/update diagnostics. Open eligibility policy separately when needed; project options display names. URLs preserve panel/source selection.

Preview analysis has no assignment action because no source task was selected. Candidate results precede the historical table. Exact-content groups preserve all IDs. Mobile stacks the queue and work area; the queue remains bounded vertically. Keyboard cancellation uses native dialogs.

## Remaining acceptance

No user study or full screen-reader audit is claimed. Large queues still require a production-sized usability test. Policy is per profile, and configured Diwan identity requires organizational verification. These limits are documented rather than concealed by confidence percentages or fabricated performance scores.
