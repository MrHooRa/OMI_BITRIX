# الاستفادة من Rab6 في توصية الموظفين

الإصدار `task-scoped-3.2` — 4 أكتوبر 2026.

## نطاق المراجعة

المرجع هو `Rab6-Project` الحالي. تمت قراءة الشيفرة والتوثيق ولقطة موجودة لملف الموظف، دون تشغيل المشروع أو استيراد وحداته أو الاتصال بقاعدة بياناته أو تعديل ملفاته. هذه مقارنة للكود وتصميمه وليست نتيجة اختبار حي لنظام رابط. التطبيق المعدّل هو OMI Bitrix في Diwany فقط.

## ماذا وجدنا وماذا تبنّينا؟

| ملف المرجع | الفكرة المفيدة | التطبيق الحالي |
|---|---|---|
| `back-end/tagging.py` | وسوم مصنفة حسب المجال والأداة ونوع العمل والمخرج والمفهوم | قاموس محلي ثنائي اللغة في `employee_insights.py`، مع توضيح أن الوسوم وصف للأعمال وليست مهارات معتمدة. لم نخمّن أسماء مشاريع أو حالات استخدام من النص. |
| `back-end/employee_search_engine.py` | استرجاع الموظفين مع أدلة يمكن فحصها | البحث في ملفات الأدلة بالاسم أو التصنيف، وفصل هذا البحث عن ترتيب ملاءمة المهمة. |
| `back-end/employee_profile.py` | تجميع الأعمال والوسوم لكل موظف مع إزالة تكرار الربط | ملف يربط المنفذ بالسجل المكتمل، يصنف أعماله ويحسب تكرار المجالات ويعرض التاريخ بصفحات. |
| `back-end/task_force.py` | تغطية المطلوب وإظهار الجوانب الناقصة وتجميع خبرات متكاملة | تغطية محسوبة من الأمثلة المكتملة المرتبطة، مزج معلن داخل مكوّن التشابه، واقتراح تكامل خبرات دون أي إسناد جماعي. |
| `front-end/src/pages/SearchPage.tsx` | البحث ثم بطاقات موجزة وتفاصيل عند الحاجة | بطاقات مرشحين قابلة للمقارنة، «لماذا هذا الموظف؟»، وتفاصيل الدرجة وفتح ملف الأدلة. |
| `front-end/src/pages/ProfilePage.tsx` | هوية الموظف ثم المجالات ثم سجل الأعمال والعودة للبحث | ملف أدلة داخل مساحة المهام، مع رجوع لنتائج التحليل، وعدد المهام المفتوحة منفصلًا. |
| `front-end/src/components/admin-editors/TaskForceAdvisor.tsx` | فهم المهمة قبل عرض المرشحين | عرض التصنيفات المستخرجة ثم المرشحين والتغطية ثم الأدلة، مع إبقاء التأكيد البشري وصلاحيات الإسناد. |

## ما لم ننقله ولماذا؟

- قاعدة PostgreSQL وواجهة React أو اعتماد LLM: المشروع الحالي Flask وJavaScript محلي، ولا يحتاج خدمة أو تنزيل نموذج جديد.
- أسماء الموظفين والبريد والهيكل الإداري كميزات ملاءمة: لا تثبت خبرة تنفيذ المهمة. الاسم مفيد للبحث فقط.
- رفع خبرة الموظف لمجرد كونه منشئًا أو مراقبًا: يستخدم الترشيح المنفّذ المسجّل للعمل المكتمل، مع بيان محدودية هذه القرينة.
- تحويل أعلى درجة في المجموعة إلى 100: الدرجة الحالية مجموع مكونات معلنة وليست احتمال نجاح.
- متجهات تجزئة الكلمات ذات 64 بُعدًا في `task_force_embeddings.py`: ليست نموذج فهم دلالي مدرّبًا، وقد تُدخل تصادمات. لم نسمِّها نموذج ذكاء اصطناعي دلالي.
- بيانات الموظفين أو الاتصال أو هوية رابط البصرية: لا تُنسخ إلى المنصة الحالية.

## رحلة المستخدم

1. يفتح المستخدم «المهام والتشابه والإسناد»، ويحدد مصدره ومشروعه، ثم يصف المطلوب.
2. يرى فهم المهمة المحلي والمرشحين. لكل مرشح حجم الدليل والضغط الحالي والمجالات المدعومة والتي لم تظهر.
3. يفتح «لماذا هذا الموظف؟» لفحص الأعمال، أو تفاصيل الدرجة لفهم الترتيب.
4. يفتح ملف الأدلة لاستعراض سجل الموظف، ثم يرجع لنتائج التحليل. تبويب أدلة الخبرات يسمح أيضًا بالبحث والتصفية المستقلين.
5. إذا كانت المهمة تحت إشرافه، يختار المنفذ ويؤكد القرار. تبقى مراجعة صلاحية المصدر وحداثة المهمة على الخادم كما كانت.

استخدمت البطاقات والمساحات والحدود متغيرات التصميم الموجودة، دون ألوان أو خطوط أو مكتبات جديدة. تعمل المكونات بالاتجاهين وبالوضعين الفاتح والداكن، وتتحول البطاقات إلى عمود على الهاتف. التفاصيل الطويلة مطوية افتراضيًا.

## البيانات والحساب

لا بيانات تدريب جديدة ولا مخزن أعمال جديد. المصدر هو تاريخ Bitrix/Diwan المتاح للملف الشخصي، مع شروط اكتمال وتواريخ صحيحة. التصنيف محلي قائم على قواعد صريحة. دليل الحساب خطوة بخطوة والمعادلات في [ALGORITHM_AR.md](ALGORITHM_AR.md).

تحسينات سلامة المخبأ المصاحبة: إبطال التاريخ عند تبديل الاتصال/نطاق المشاريع/ربط الحقول، ومعرّف مراجعة مستقل لكل لقطة ناجحة حتى لو حدث التحديث مرتين في الثانية نفسها. يبقى الجدول كل ساعتين للتاريخ وكل دقيقة للمهام المفتوحة أثناء التشغيل.

## التحقق والحدود

اختبارات آلية مستقلة للوسوم العربية والإنجليزية، التعارض بين المجالات، التغطية الجزئية، معادلة المزج، استقلال الاسم عن الترتيب، تكامل الخبرات، عزل الملفات والمصادر، صفحات السجل، تبديل الاتصال، وتجدد الفهرس. راجع [testing.md](testing.md) لنتيجة التشغيل النهائي.

التصفح اليدوي الآلي يستخدم بيانات اصطناعية في خادم اختبار منفصل، دون إدخالها في Bitrix أو بيانات التشغيل. لا يثبت ذلك جودة التوصيات على كل بيانات المؤسسة. يلزم تقييم بشري لمجموعة مهام متنوعة قبل اعتماد معاملات ترتيب جديدة مؤسسيًا. كما يبقى تكامل ديوان الحي غير متحقق لعدم توفر عينة معتمدة. لا يكتشف القاموس الحالي جميع المجالات أو الأخطاء الإملائية أو المهارات الضمنية، ولا يصنّف الأشخاص وظيفيًا أو يحكم على أدائهم.
